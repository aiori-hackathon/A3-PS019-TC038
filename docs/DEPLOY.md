# Deploying PrivacyTwin

The API and the frontend deploy separately. The frontend is plain static files.

## Render: single container (used for the live demo)

`render.yaml` defines one free **Docker** web service named `privacytwin`, built from `Dockerfile.render`:

1. The first stage builds the Next.js frontend as static files with `NEXT_PUBLIC_API_URL=same-origin`.
2. The runtime stage installs the Python API and serves those files from the same address, so the browser calls `/api` on its own origin (no CORS setup needed). The health check is `/api/health`.
3. `autoDeploy: true`: every push to `main` rebuilds and redeploys.

In the Render dashboard, set **`GROQ_API_KEY`** (optional; enables Ask AI, the AI analyst and auto-triage). `PRIVACYTWIN_SECRET` and `PRIVACYTWIN_FINGERPRINT_PEPPER` are generated by the blueprint.

The free plan has no persistent disk: workspaces reset when the service restarts, redeploys or sleeps (after ~15 minutes idle). The app shows a wake-up screen and retries automatically. To keep it warm, set the repository variable `API_HEALTH_URL` (e.g. `https://privacytwin.onrender.com/api/health`); `.github/workflows/keepalive.yml` pings it every 10 minutes during the day.

Rehearse the container locally without Docker:

```bash
cd web && NEXT_PUBLIC_API_URL=same-origin npm run build && cd ..
PRIVACYTWIN_STATIC_DIR=web/out uvicorn privacytwin.api:app --port 10000   # open http://127.0.0.1:10000
```

## Frontend on Vercel

1. Import the repository; set **Root Directory** to `web`.
2. Add the environment variable `NEXT_PUBLIC_API_URL=https://<your-render-service>.onrender.com` (and optionally `NEXT_PUBLIC_SITE_URL` for Open Graph URLs).
3. Deploy. `web/vercel.json` sets the output directory (`out`) and security headers. If your API is not on `*.onrender.com`, add its origin to `connect-src` in the CSP.

## Any static host

```bash
cd web
NEXT_PUBLIC_API_URL=https://api.example.com npm run build   # writes web/out/
```

Serve `web/out/` with any static server (directory-style URLs, e.g. `/app/overview/index.html`).

## Environment variables (API)

| Variable | Default | Purpose |
| --- | --- | --- |
| `PRIVACYTWIN_DB` | `data/privacytwin.sqlite3` | Application database path |
| `PRIVACYTWIN_ALLOWED_ORIGINS` | `http://localhost:3000,http://127.0.0.1:3000` | CORS and CSRF origin allow-list |
| `PRIVACYTWIN_SECRET` | random per process | CSRF HMAC key (set it so tokens survive restarts) |
| `PRIVACYTWIN_FINGERPRINT_PEPPER` | built-in dev value | Server-side key for value fingerprints. **Set in production** |
| `PRIVACYTWIN_STATIC_DIR` | unset | Serve the built frontend (`web/out`) from the API (single-container mode) |
| `PRIVACYTWIN_WARM_EVAL` | `1` | Pre-compute the benchmark at start-up |
| `GROQ_API_KEY` | unset (locally: `data/groq-key.txt`) | Enables the Groq LLM for the AI analyst, Ask AI and Explain with AI. Sends metadata only |
| `GROQ_MODEL` | `openai/gpt-oss-120b` (auto-fallback if retired) | Groq model |
| `PRIVACYTWIN_LLM_URL` / `_MODEL` / `_KEY` | unset | Any other OpenAI-compatible endpoint instead of Groq |
